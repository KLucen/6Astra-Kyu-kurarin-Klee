# 本次 PV 制作复盘与通用 SKILL 提炼

日期：2026-10-10。复盘对象为本目录 Kyu-kurarin 角色替换工程，最终可用输出是 ALICE_v4 草稿。具体帧号、素材和参数只属于本工程；通用 SKILL 按来源、独立绘稿、曝光、实例和图层复杂度工作。

## 实际完成的流程

| 环节 | 本次采用的方法 | 证据入口 |
| --- | --- | --- |
| 来源固定 | 同一源片顺序解码，记录 SHA、6338 帧的精确 PTS、1920×1080、画面结束 216.0700625 秒及原 AAC | `analysis/source_meta.json` |
| 镜头与绘稿分析 | 概览定位，原尺寸候选与局部差值确认姿势、口型、睁闭眼；人物变化与相机、歌词、背景分开 | `scripts/candidates.py`、`pose_analysis.py`、`mouth_audit.py` |
| 生成与选稿 | 当前源稿负责动作/表情，角色参考负责身份，已选稿负责连续性；生图前保存任务，输出后登记尺寸/SHA与使用范围 | `jobs/`、`generated/`、`assets.json` |
| 跟踪与实例 | 用源特征配准获取位置；一对多描述子匹配/位移投票寻找回声副本；限定真实区域修复跨姿势误配 | `scripts/track_scenes.py`、`track_body.py`、`repair_echo_props.py`、`repair_body_tail.py` |
| 分层合成 | 当前源帧作为底图，清除旧人物并合成新人物；文字、道具、背景按自己的时间变化恢复 | `scripts/composite_core.py`、当前曝光表 |
| 定向返修 | v2 修口型/入退场；v3 换闭眼拥抱对象；用户反馈后 v4 补上睁眼对象，保留前版有效部分 | `analysis/mouth-repair-v2.json`、`alice-v3-change-scope.json`、`alice-v4-change-scope.json` |
| 输出与检查 | 依原 PTS 编码，复制原 AAC；从完成主片制作左右对照；主片、预览、对照分别验证 | `analysis/alice-v4-technical.json`、`alice-v4-comparison-technical.json`、`alice-v4-full-hug-preview-technical.json` |

累计保存 30 张生成候选，采用 24 张；4 张因腿向、多余鞋或裁切错误被替换，2 张旧拥抱对象稿成为历史版本。这些数字是本次采用记录，不证明所有原手绘变化已经完整迁移，也不是另一支 PV 的生图配额。

## 最有价值的返修经验

前后拥抱由两种表情稿驱动。v3 只改 `[6039,6264)`，即闭眼段；用户随后指出前段仍未修改。v4 补上 `[5784,6039)` 的睁眼段，保持已经完成的后段。应把用户时间码和动作名称转换为人物、表情阶段、重复实例及曝光清单；不能仅凭内部文件名判断用户实际指向的范围。用户明确限定阶段时，也不能擅自扩大修改。

补稿以已核双人构图为编辑基线，只让另一张参考提供睁眼、眉毛、嘴形和泪滴，避免把旧拥抱对象带回。配角身份、原有单色背影表现和主角的情绪分别约束。若源稿还有手势或轮廓变化，应继续迁移这些变化，不能把局部换表情当作所有动作的替代。

模型输出不能靠提示词实现像素锁定。此次通过应保持的共同特征测量新旧稿，显式换算 PNG 与标准画布坐标。新睁眼稿对闭眼稿的配准有 692 个内点、中位残差约 0.446 像素；这些数值是辅助证据，仍需看身体、双手和配角轮廓。变换链记录于 `analysis/alice-open-cel-registration.json`。

“其他不变”要分层说明。v2 的实际重编码 GOP 比美术修改范围大，报告中的区间外不变字段来自脚本声明，不能当作独立哈希验证。v4 针对已核编码结构只替换 255 帧，实际比较其余 6083 个视频包载荷，并对修改前后关键边界比较解码像素；音频由独立检查器核对载荷及时间戳。此法依赖编码条件，不是任意视频可用的拼接算法。

完整拥抱预览覆盖 `[5784,6264)` 的两种表情，共 480 帧、16.364 秒。只展示成功修改的一小段，会掩盖相邻阶段仍未覆盖的问题；预览应与用户反馈对象对应。

## 没有达到终版的部分

- 绘稿细节比原 PV 更精细，简化画风还需统一。
- 部分手绘线条/轮廓变化没有逐稿迁移；若源稿确实不同，不能用相同素材复用宣称完全保留。
- 少数入场跟踪采用待审的同相位备用值，不能当成已确认源配准。
- 旧角色颜色检测在 224 帧花形道具边线触发，已核为保留物；颜色报警不能单独判定旧角色残留，也不能由局部豁免推断全片干净。
- 已完成静帧和技术检查，尚未实际观看完整原速播放。因此仍是草稿，技术通过不能授予美术终版状态。

## 写入通用 SKILL 的原则

1. 每次重新实测来源；帧数、时序、画布、循环、图层与资产映射作为当前项目数据。
2. 总帧数影响解码/合成/编码规模；独立绘稿、实例、相位和风险决定生图与美术工作量。
3. 长持帧/重复多时复用已经核定的稿；动作密集时充分拆稿；连续运镜先分离相机；多人物时逐实例跟踪。
4. 长片通过流式处理、依赖批次、磁盘缓存和恢复检查点提速，不降低关键动作、字幕和原速检查要求。
5. 返修先明确语义覆盖，再做几何配准及局部合成；区分美术修改范围与实际重编码范围。
6. 高质量标准适用于任何长度，数量、抽样比例和技术检查项数均不能替代内容验收。

具体项目脚本和历史另一支 PV 的专用目录不再作为 SKILL 的操作依赖。原 SKILL 文档保存在 `analysis/skill-review-2026-10-10/before/`；本地复盘、视频与生成素材不进入 Skill 仓库。
